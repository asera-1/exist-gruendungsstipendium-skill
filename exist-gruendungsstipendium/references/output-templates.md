# Working templates

These are optional internal working tools, not additional application forms. Select the smallest useful template for the active mode. Do not make the founder complete all of them, and do not expose internal ledgers when a short answer is enough.

## Template routing

| Mode | Start with | Add only if needed |
|---|---|---|
| Fit check | Eligibility matrix | Founder profile for unresolved person/team facts |
| Application setup | Founder profile and combined claim/evidence ledger | Evidence index, master plan, customer or finance register |
| Draft | Section brief internally | Filtered claim/evidence rows for the requested section |
| Form or budget | Form/cost field map | Founder profile or financial assumptions |
| Review | Coverage statement and reviewer-rubric finding table | Relevant ledger rows only where they substantiate a finding |
| Finalize/handoff | Coverage statement and readiness handoff | Gründungsnetzwerk meeting brief |

Keep the current applicant's authorized information private. Do not place sensitive names, codenames, contacts, identifiers, unpublished technical details, private quotations, or exact private financials in searches, URLs, external tools, examples, repositories, or public artifacts.

## 2. Combined claim and evidence ledger

Use one row per material claim. The dimensions are independent; do not turn them into one status.

| ID | Claim | Kind | Evidence support | Temporal state | Evidence/source | Limitation | Used in | Owner/action |
|---|---|---|---|---|---|---|---|---|
| C-001 |  | fact / estimate / hypothesis / inference | supported / partly supported / missing / conflicted / not checked | current / funded target / post-funding target |  |  |  |  |

An applicant record supports only what it directly demonstrates. For example, interview notes may support that interviews occurred and what participants reported; they do not automatically establish market-wide demand.
